# go-retry

又在终端里为个编码解码去开浏览器搜网页？别了，一行命令的事。

指数退避重试，零依赖，只用标准库。既是个能包住任意命令的 CLI，`backoff.go` 也能直接抠出来当库用。

## 编译

```
go build -o go-retry.exe
```

## 用法

命令失败就按退避间隔重试，`--` 后面是要跑的命令：

```
go-retry -n 5 -base 1s -- curl -f https://example.com
```

不想真跑，只看退避计划长什么样：

```
> go-retry -n 6 -base 200ms -factor 2 -plan
最多 6 次，起步 200ms，倍数 2.00，上限 10s，抖动 20%

第 1 次失败后等 200ms      累计 200ms
第 2 次失败后等 400ms      累计 600ms
第 3 次失败后等 800ms      累计 1.4s
第 4 次失败后等 1.6s       累计 3s
第 5 次失败后等 3.2s       累计 6.2s

最坏情况总等待 6.2s（不含命令本身耗时）
算上抖动大概在 4.96s ~ 7.44s 之间
```

## 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `-n` | 5 | 最多试几次，含第一次 |
| `-base` | 200ms | 第一次重试等多久 |
| `-max` | 10s | 单次等待上限 |
| `-factor` | 2 | 每次间隔乘多少 |
| `-jitter` | 0.2 | 抖动比例，0~1 |
| `-total` | 0 | 总耗时上限，0 表示不限 |
| `-plan` | false | 只打印退避计划 |
| `-q` | false | 不打印重试过程 |

## 实现上注意的几点

- **指数会溢出**：次数多了 `base * factor^n` 会超过 float64 上限变成 `+Inf`，转成 `time.Duration` 就是个负数，然后 timer 立刻触发，退避完全失效。这里会检测溢出直接顶到上限。
- **抖动不能抖出负数，也不能冲破上限**。抖动是为了避免一堆客户端在同一毫秒集体重试，把服务端再打挂一次。
- **不该重试的错误要立刻放弃**：像参数错、404 这种重试多少次结果都一样。用 `WithRetryable` 指定判断逻辑。
- **总时长上限会提前刹车**：不会因为次数还没用完就一直等下去。剩余预算不够一次完整退避时，等待会被截短。
- **Ctrl+C 立刻生效**：等待是 `select` 在 timer 和 `ctx.Done()` 上的，不会干等完退避才响应。
- **错误用 `%w` 包着返回**，上层可以 `errors.Is` 到原始错误。

## 当库用

```go
res, err := Do(ctx, DefaultPolicy(), func(n int) error {
    return doSomething()
}, WithRetryable(func(err error) bool {
    return !errors.Is(err, ErrNotFound) // 404 不重试
}))
```
